# NailSeed v0.8 — the parser moves into Nail

NailSeed is still bootstrapped by the Haxe parser, but **the new recursive expression/program parser is implemented in `stdlib.nail`**, alongside the tokenizer introduced in v0.7.

The parser constructs **structured, first-class `Syntax` values** rather than the flat text list from `parseTinyDef`. It recognizes a deliberately bounded grammar: names, finite decimal and integer literals (stored lexically), booleans, empty and nonempty lists, parentheses, function application, infix arithmetic/comparisons with precedence, `fun`, `if`, `let`, top-level `def` and expression forms. It reports malformed input as a `Syntax` error leaf rather than silently returning an empty list.

Examples after `vm.loadStdlib()`:

```nail
parseSource " def twice x = x * 2 ; " ;
parseSource " def add a b = a + b ; add 3 4 ; " ;
parseSource " if true then [ 1 , 2 ] else [] ; " ;
```

Use `syntaxTag`, `syntaxText` and `syntaxChildren` to inspect the returned tree. For example, `syntaxTag ( parseSource " 1 + 2 ; " ) ;` returns `"Program"`.

A `Syntax` tree uses immutable leaves and nodes, created by the host primitives `syntaxLeaf tag text` and `syntaxNode tag children`. These extend **the value domain and type inference (`Syntax`)**, NOT the five-node executable expression AST (`Literal`, `Var`, `Lambda`, `Apply`, `If`). Parser results are ordinary first-class Nail values.

## Running the tests

From `v0.8/` with Haxe 4.3.7:

```sh
haxe test-interp.hxml
haxe type-test-interp.hxml
haxe parser-test-interp.hxml
```

JavaScript and PHP builds, tests and downloadable artifacts are generated by [GitHub Actions](../../.github/workflows/nailseed-v08.yml). The self-parser suite compares its syntax trees against the independently implemented Haxe bootstrap parser, including malformed inputs, on all three execution targets.

## Limits and next steps

- **Not full self-hosting**: the runtime and initial parser remain in Haxe. This is a source-level parser for a subset of Nail; it does not compile or evaluate the trees it returns.
- Does not yet parse quoted-text literals, comments inside source, `match` patterns, arbitrary Unicode strings or newer numeric formats. Quoted text is still supported by the Haxe bootstrap parser, but not yet by `parseSource`.
- Tokens in the inner source must still be separated by spaces. The tokenizer is written in Nail using ASCII text primitives and the parser uses recursive calls (no tail-call optimization).
- `Syntax` nodes permit heterogeneous *children as Syntax trees*, but Nail lists remain homogeneous. This avoids adding dynamic values or undermining Hindley–Milner inference.
- The parser returns an `Error` leaf on invalid syntax; source locations and error recovery are deferred.
- Floating-point numbers continue to be IEEE 754 as in v0.7. Exact rational arithmetic is a separate experiment.

Historical versions v0.1 through v0.7 are preserved unchanged.
