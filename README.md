# NailSeed v0.13 — Iterative structural tooling

NailSeed v0.13 improves the *tooling around* the already-iterative AST and bytecode VMs. It does not change Nail source syntax, the five core AST constructors, numeric semantics or structured bytecode opcodes.

## What changed

- `src/nail/SyntaxBridge.hx`: decodes `Syntax` into core `Expr` with a bottom-up work stack, including strict arity, literal and error validation.
- `src/nail/SyntaxEncoder.hx`: encodes the host AST into `Syntax` with explicit post-order frames.
- `src/nail/BytecodeCompiler.hx`: iteratively lowers the core AST to structured bytecode. Tail calls and terminal branches retain the v0.12 semantics.
- `src/nail/TypeChecker.hx`: expression inference, unification, occurs check, type generalization traversals, normalization, instantiation and type formatting use iterative loops. Lexical let-generalization and equality constraints are preserved.
- `src/nail/Parser.hx`: collapses contiguous redundant parenthesis runs without recursive host calls for each opening delimiter. The general Pratt parser **still contains recursion** for nested expression forms.
- `src/StructuralDepthTestMain.hx`: seven structural-depth tests exercise 7,000 nested lambdas, 6,000 conditions, 3,500 applications, malformed nested Syntax, deep grouping, and the generated bytecode.

## Run the tests

Install Haxe 4.3.7, then from `v0.13/`:

```sh
haxe structural-test-interp.hxml
haxe structural-test-js.hxml && node build/tests/structural.js
haxe structural-test-php.hxml && php build/tests/php-structural/index.php
```

The GitHub Actions workflow `.github/workflows/nailseed-v013.yml` also runs the entire historical test suite across Haxe `--interp`, JavaScript and PHP before publishing compiled artifacts. All previous versions remain separate.

## Remaining bootstrap work

This is **not full self-hosting**. The host `Parser.hx` still starts the standard library; the Nail-written parser/compiler are loaded through that first stage. Expression parsing of arbitrary nesting, `SelfParserV09TestMain`'s canonicalization helper, other fixture code, and memory/time bounds for excessively deep programs remain distinct tasks. The checker still allocates environments for lambda scopes, so large inputs can be expensive even without a native call-stack overflow.

The deliberately restricted whitespace tokenization rule is unchanged. See [SPEC.md](./SPEC.md) for invariants and limitations.
