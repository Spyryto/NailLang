# NailSeed v0.11 — Tail-call optimization

This version makes **tail recursion run with constant host call-stack depth** in the Haxe ByteVM (and its JavaScript/PHP builds). It preserves the structured bytecode design and five-node source AST from v0.10.

## Tail calls

The compiler emits a new terminal opcode, `TAIL_CALL`, when function application is in **tail position**, including inside a final branch of `if`. `CALL` is retained for non-tail calls and argument computations.

The ByteVM returns a `TailInvoke(fn, arg)` outcome instead of invoking the next closure recursively; a trampoline loop replaces the current activation with the callee's environment. Tail branches directly propagate the outcome. A `TAIL_CALL` in a non-tail block or before further instructions is rejected as malformed bytecode.

Only **one new opcode** was added. There are still five source AST variants: `Literal`, `Var`, `Lambda`, `Apply`, `If`. Code generation is implemented both in Haxe (`BytecodeCompiler.hx`) and in Nail (`compileTail` in `stdlib.nail`). Their generated bytecode is compared structurally by the tests.

```nail
def loop n acc =
  if n == 0 then acc
  else loop ( n - 1 ) ( acc + 1 ) ;
loop 30000 0 ;
```

This example is run through the **bytecode runtime**. The old AST evaluator has not yet been converted to a trampoline; normal non-tail recursion continues to consume host stack.

## Test and build

From the v0.11 directory, with Haxe 4.3.7:

```sh
haxe bytecode-test-interp.hxml
haxe bytecode-test-js.hxml && node build/tests/bytecode.js
haxe bytecode-test-php.hxml && php build/tests/php-bytecode/index.php
```

The cross-target regression covers the v0.10 compiler and runtime tests, new tail/non-tail equivalence cases, a 30,000-step self tail recursion, 20,000 mutual tail calls, and step-budget enforcement. The existing parser, type-checker and integration tests also run in GitHub Actions.

The compiler bootstrap test now loads the new `bcTailCall` and tail-aware `compileGo` with wrapper `compileTail` (14 compiler definitions total).

## Limitations

- Only bytecode-compiled execution uses tail-call elimination; `Vm.run()` still uses host recursion.
- `BRANCH` and `CLOSURE` still contain nested structured instruction blocks rather than flat jump offsets.
- `TAIL_CALL` replaces a frame only in terminal position; arbitrary non-tail recursion is not optimized.
- This is an experimental compiler/VM, not a bytecode sandbox or a full self-hosted toolchain.
- JavaScript and PHP build artifacts are generated by CI and are not checked in.
