# NailLang 0.55 — Type checker Nail e percorso provider verificato

## Ambito della release

Nail 0.55 consolida la verifica autonoma della semantica dei programmi
con il checker scritto in Nail stesso, lasciando Haxe come riferimento
indipendente e come livello host/serializzazione dove necessario.

**La priorità della 0.55 è la correttezza, non le prestazioni.**

### Checker e metaprogrammazione

- Checker HM implementato in Nail per il sottoinsieme supportato,
  con confronti differenziali sui target Haxe, JavaScript e PHP.
- Espansione delle macro igieniche, import selettivi/transitivi di moduli
  macro, gestione dei cicli, controlli di budget cumulativo e diagnosi.
- Conservazione degli schemi generali da un'unica verifica completa del
  programma, senza rieseguire l'inferenza per costruire gli export.
- Schemi canonici con variabili polimorfiche, `Eq`, record strutturali
  aperti e vincoli negativi `row-lacks`.
- Importatore sperimentale che istanzia variabili fresche e ripristina
  vincoli `Eq` e `row-lacks` del preview.

### Provider compilato e tracciabilità

- `tcCompileDeclaredModulePreview` produce **insieme** le firme degli
  export e il bytecode dalla stessa struttura espansa e verificata.
- `NailCheckedModuleEnvelope` trasporta canonicamente la coppia e
  include SHA-256 per il controllo d'integrità, con verifica di ogni
  export contro una definizione compilata.
- `NailPinnedProviderRebuild` confronta l'artefatto con una
  ricompilazione ottenuta da **sorgente e bootstrap con hash approvati
  indipendentemente dall'host**. Rifiuta anche bytecode alterato con
  un hash interno ricalcolato.

### Compatibilità e confini

- Nuovo header: `nail 0.55 ;`. I domini `Int`, `Ratio`, `Float`
  e gli import selettivi già disponibili nella 0.54 restano supportati.
- **Il formato pubblico dei moduli resta
  `nailseed.runtime-module.v3`**: non esporta tipi con code
  strutturali aperte e non accetta l'artefatto preview come import
  eseguibile.
- Le dichiarazioni `export nome ;` per valori sono consentite nel
  **solo percorso preview opt-in**: l'importazione ordinaria dei moduli
  runtime continua a passare da `ModuleLinker.compilePublic`.
- Un hash non costituisce una firma Ed25519, una prova di correttezza
  del compilatore o un'attestazione dell'identità di un publisher.
  La verifica per ricompilazione non può fondare la fiducia usando
  impronte ricavate dallo stesso pacchetto non attendibile.
- Non vengono aggiunti `use Module { ... }`, accesso qualificato ai
  namespace, discovery ambientale, nuovi opcode o una nuova ABI pubblica.
- Prima di Nail 1.0 non è garantita retrocompatibilità. I tag
  storici e il branch `stable/0.54` rimangono disponibili.

## Verifica della release

La release è pubblicabile **solo** dopo che il commit candidato ha
superato i sette target di regressione indipendenti
(Haxe, Node e vari shard PHP), la compilazione/smoke test delle
distribuzioni senza sorgente e il job aggregatore `build-and-test`.
Il workflow di pubblicazione esegue inoltre smoke test dei binari
e prepara i pacchetti JS, PHP, boot JS, boot PHP e l'immagine bootstrap.

Sono inclusi casi di regressione per `nail 0.55 ;`, parità del
bytecode Haxe/Nail, import selettivi ed `Eq`, roundtrip dei preview,
duplicati `row-lacks`, integrità, ricompilazione da pin indipendenti
ed errori atomici.

**Nota di stato:** questo documento descrive il contenuto candidato
della versione 0.55; il tag `v0.55` e gli artefatti scaricabili
esistono soltanto quando il workflow GitHub Releases termina con successo.
