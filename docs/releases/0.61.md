# NailLang 0.61 — inferenza dei record (candidato)

Stato: **candidato non pubblicato**, in attesa dei nove job CI sul
commit finale e del workflow di rilascio. La release v0.60 rimane immutata.

## Cambiamento semantico

L'accesso `data . name` in una funzione con parametro non annotato
introduce un **requisito strutturale aperto**; non sceglie più un
record nominale in base all'omonimia del campo.

```nail
nail 0.61 ;
type Person { name Text age Float } ;
def getName data = data . name ;
getName { name = " Daniele " , age = 19.0 } ;
getName ( Person " Mario " 46.0 ) ;
```

Il tipo inferito di `getName` è equivalente a
`{name: a | r} -> a`. Funziona su record anonimi e nominali che
posseggono il campo richiesto, con eventuali altri campi.

Con l'annotazione esplicita il parametro rimane **nominale**:

```nail
nail 0.61 ;
type Person { name Text age Float } ;
def getName ( data : Person ) = data . name ;
```

Passare un record anonimo al posto di `Person` è un errore di tipo,
anche quando i campi coincidono. L'annotazione viene applicata prima
dell'inferenza, non successivamente.

## Implementazione e confini

- Riutilizza `TOpenStructural`, `unifyRows`, inferenza HM e getter
  dei record già presenti. Nessun nuovo AST, opcode o conversione runtime.
- Il parser ordinario accetta `( data : Person )` per record nominali
  monomorfi dichiarati prima della funzione nel medesimo sorgente;
  annotazioni nominali generiche restano da progettare.
- Il compilatore Nail sorgente/senza Haxe cancella già le annotazioni
  durante il lowering. Per il controllo statico della semantica
  nominale usare il checker Haxe: `BootRuntime.compile/run` non
  impongono automaticamente un typecheck, come già nelle versioni precedenti.
- Il checker alternativo scritto in Nail rimane sperimentale e non
  è ancora dichiarato equivalente per questo nuovo caso.
- Gli schemi aperti non sono ancora esportabili tramite l'ABI pubblico
  dei moduli. Il linker resta conservativo.
- Le vecchie release GitHub, inclusa v0.60, non sono sostituite.

## Verifica

La suite `structural-projection` controlla tipi generici, esempi nominali
e anonimi, casi negativi, oscuramento lessicale, esecuzione VM normale
e bootstrap su Haxe, Node/JS e PHP.

La pubblicazione richiede anche i nove job CI sullo **SHA esatto**
e gli smoke della distribuzione source-free JS/PHP con header v0.61.
