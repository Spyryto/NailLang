# NailLang 0.62 — candidato

Stato: in validazione sul branch di integrazione. Non è una release pubblicata.

## Linguaggio

```nail
nail 0.62 ;
def fraction numerator: a denominator: b = a / b ;
def add-three = ( fun x -> x + 3 ) ;
3 >> fraction denominator: 2 ;
4 >> add-three ;
```

- Identificatori con trattini; gli operatori aritmetici restano token separati.
- Argomenti posizionali e nominati, label pubbliche distinte dal binder locale, currying anche non prefisso.
- Pipeline sinistra-destra `>>`, con precedenza inferiore all'aritmetica e ai confronti.
- Vincoli numerici inferiti: `def summ x y = x + y ;` conserva il predicato Add; ogni uso istanzia indipendentemente lo schema. Le divisioni esatte preservano Ratio; Int e Ratio non vengono convertiti implicitamente a Float.
- I confronti ordinati inferiscono Bool con lo stesso dominio numerico.

## Implementazione

La stdlib rifattorizzata è ora il sorgente canonico `stdlib.nail`; non esiste più una patch necessaria al build. I test differenziali recuperano il sorgente 0.61 dal commit storico `672aba14a139b2e56c9acfeb5d9b4adf2e938f5d`, non da una seconda copia mantenuta.
La sintassi nuova è abilitata nel parser Haxe per la 0.62 e per i sorgenti senza intestazione, necessari anche al caricamento legacy della stdlib. Gli header precedenti restano accettati, ma non selezionano una toolchain storica: in particolare il parser e checker Nail canonici condividono l'implementazione nuova. Per riprodurre esattamente una versione precedente, usare il tag e la distribuzione di quella versione.

Non sono stati aggiunti costruttori Core AST, opcode o formati ABI. Le label non sono proprietà first-class esportate; nel parser Nail restano locali alla singola unità. Il percorso Haxe conserva i metadati delle definizioni riuscite nelle sessioni. Le chiamate nominate in contesti DSL aperti e i moduli con schemi numerici qualificati non sono ancora supportati.
